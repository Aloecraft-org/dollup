Get started 4 commands
$curl -fsSL https://dollup.aloecraft.org/install.sh | sh
$dollup init
$dollup source add https://dollup.aloecraft.org/std-repo/ \
--key __DOLLUP_STD_PUBKEY__
$dollup add hello

You now have the program, everything it depends on, and a lockfile recording exactly which bytes arrived. Point DRT at the directory to run it.

Get started pre-release
$curl -fsSL https://dollup.aloecraft.org/install.sh | sh
$dollup init

That installs a verified binary and starts an app. The standard package repo is not published yet — when it is, its signing key will appear on this page and dollup init will point at it. Until then, releases are at GitHub.

An app

One directory holding your programs, the sources they came from, and a lockfile pinning every version and hash. Copy it to another machine and you get the same thing, byte for byte.

Verified on the way in

Packages are named by the hash of their contents and listed in an index the publisher signs. The same package from this mirror, a git remote, or a zipball is a single artifact.

Nothing executes on install

A manifest is data and can express no behaviour. What a program is allowed to do stays in your config — installing something never grants it anything.

Verifying this repo
__DOLLUP_STD_PUBKEY__

A verified index means a holder of this key signed exactly these bytes — authenticity, not freshness.

Standard repo

Not published yet. When the standard repo goes live its ed25519 signing key is shown here, and you pin it in your source list — an ordinary line in a file you own. A verified index means a holder of that key signed exactly these bytes: authenticity, not freshness.
